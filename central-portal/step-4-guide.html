MILESTONE 1 · STEP 4

Build a simple baseline

A baseline is a straightforward method that answers the same question as your Step 3 soft-computing method. Comparing both methods helps you show what your method improves.

Before you start

  • Finish and submit Step 3 first. Keep your Step 3 code and outputs; do not replace them.
  • Use the same dataset or test scenarios, input format, and evaluation measure for both methods.
  • Work in your team's repository. Create a new branch such as step-4-baseline from the branch containing your completed Step 3 work.
  • Agree with your team on one simple, reproducible baseline. It should not secretly use the advanced method you are comparing against.

Actions to complete

  1. Write the comparison question. In docs/STEP-4.md, name the output you predict or optimise and the measure you will compare. Example: “Does the ANN classify potability more accurately than a majority-class baseline on the same test set?”
  2. Choose the simple rule. Write down the baseline before you code it. Examples are in the table below. Explain why it is a fair starting point, not a final product.
  3. Implement it. Add a clearly named notebook or Python file, such as notebooks/03_baseline.ipynb and src/baseline.py. Use your own project's code. Do not paste the SC11 ANN code into a different project.
  4. Run both methods on matching inputs. Keep the same train/test split or identical test scenarios. Fix random seeds where relevant. Do not fit or tune on the held-out test set.
  5. Compare results. Save a small table with baseline result, Step 3 result, difference, dataset or scenario count, and measure definition. Save at least one graph or representative input/output example.
  6. Explain the result. Say where the advanced method helps, where it fails, and any limitation. Do not claim improvement if the evidence does not show it.
  7. Commit and sync. Stage only relevant files, write a meaningful commit message, sync/push the branch, then confirm the files and latest commit appear on GitHub.
  8. Submit Step 4. Open your team dashboard, select Step 4, enter the public project repository URL and a short note pointing to the baseline comparison, then submit. Check that the dashboard says Step 4 is submitted.

What your repository should show

  • Baseline code that another student can run, with dependencies and run instructions.
  • An executed notebook with visible outputs if your project uses notebooks.
  • A comparison table or CSV and at least one useful figure/example.
  • docs/STEP-4.md explaining the baseline rule, data split/scenarios, metric, results, limitations and each member's contribution.
  • A meaningful Step 4 commit visible on GitHub. Your Step 3 work must still be accessible.

Step 4 is not Product V1. Step 5 will connect your method to an input/output interface. Here, the goal is to establish a fair reference and show an honest comparison.
